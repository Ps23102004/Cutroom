# Corrections to older Cutroom image concepts

The latest written requirements and master mandate take precedence over all older generated image labels. The owner's current design ZIP must be inspected locally; this packet does not claim to contain or have reviewed it.

## Preserve

A minimal dark charcoal/plum theme; restrained violet interaction accents; warm ochre and maroon character; sky-blue information and light-green positive states; readable off-white text; purposeful depth; optional tasteful real 3D motion.

One shared desktop shell and a canonical eight-item navigation order:
Home, Projects, Studio, AI Briefs, Review, Versions, Deliver, Settings.
Jobs and Help are footer utilities. Client review/public pages have explicitly role-appropriate simpler layouts with shared tokens.

## Remove or correct

- Home is not a repeated marketing landing page. Remove giant slogans and invented completion percentages.
- Keep palette/material/object presentation boards out of the app. Actual user-editable brand colors belong only in Brand controls.
- Remove random dragons, balls, model mascots, enormous decorations, ambient bloom, and luminous borders on every panel.
- Do not independently generate all UI screenshots and treat their inconsistent navigation as a specification. Build and capture the shared interface in code.
- Split project listing, media management, brief, plan, run progress, comparison, output setup, queue, and package into focused views.
- Do not infer a 3D import library, a marketplace, synthetic B-roll/video, or social publishing from illustration content.
- Do not hardcode fictional model names, parameters, download sizes, health states, or install counts.
- A text/embedding/ASR model is not automatically an image generator, speech generator, or renderer.
- Support 4K/HDR/RAW only when implemented and certified, not because a thumbnail has a 4K badge.
- Do not show “everything local” and a real upload as the same privacy promise.
- Do not provide a universal “no training” switch that cannot control third-party provider behavior.
- “Label approved” cannot replace authenticated exact-version approval. Never transfer old approval automatically to edited content.
- No fabricated E2EE, unlimited storage, free hosting, human support staff, or response-time promise.
- A green indicator must come from real state. A queued ticket/upload is not completed.

## Default 3D direction

Cutline: one tactile flexible strip inspired by the edit timeline, with a violet satin face, wine reverse, and warm ochre edge. Generate references only after specifying its purpose and placements. Convert to an actual mesh with the owner's installed tool, inspect/repair it, then apply state-driven motion with a static fallback. A procedural cleanup/rebuild is allowed when documented honestly.

## Release screenshots

Screenshots must be captured from implemented routes with the same component system. Development fixtures and concept artwork must be labeled; neither proves native processing, real approvals, or deployed services.
